> 版本：2026-09-24（补：跳弹概率曲线 + 大口径 HE 毁伤体系 + fire() 字段转发坑）
> 配套文件：`炮弹数据总表.md`（24 车最终数值与史实出处）、`scripts/ammo_overhaul_20260923.py`（本次迁移脚本，TANKS 字典是字段格式范例）
> 回滚备份：`_backup_20260923_apcr/`（炮弹改造前）、`_backup_20260923_armor/`（装甲板图改造前）、`_backup_20260923_ricochet/`（跳弹改造前）

## 1. 总原则

1. **贴近史实优先，平衡其次**。穿深、初速、备弹量、弹种配置都以史实为准；只有"配弹发数"允许向下取整做平衡（见 §4）。
2. **全车统一 30° 口径**。所有 `shellPen` 一律是对 **30° 倾斜角 RHA** 的穿深。各国原始资料口径不一（苏联常用 0° 垂直、德国 30°、美国部分 0° 或 20°），录入前必须换算到 30°。
3. **AI 生成的对照表只能当线索，不能当数据源**。2026-09 这批校对里，AI 表格的穿深、初速、型号错误率很高，每个数字都要回到权威来源核实（见 §7）。

## 2. config.js 每车弹药字段格式

```js
shellName: 'PzGr.39 APCBC',        // AP 弹型号（UI 小字展示）
shellNameCn: '被帽穿甲弹',          // AP 中文注释（UI 小字展示）
shellVelocity: 773,                // AP 初速 m/s
shellPen: 119,                     // mm RHA @0m，30° 口径（注释里写史实曲线备查）
shellPenDrop: 0.15,                // 每千米穿深衰减比例（见 §3 拟合法）
apcrShell: { name: 'PzGr.40 APCR', nameCn: '钨芯穿甲弹', velocity: 930, pen: 171, penDrop: 0.18 },
heShellName: 'Sprgr.39',           // HE 弹型号
heVelocity: 810,                   // HE 初速 m/s（按炮族，常≠AP 初速）
loadout: { ap: 46, apcr: 3, he: 43 },  // 逐弹种配弹；ap+apcr+he 必须 == ammo.shell
ammo: { shell: 92, mg: 4500 },     // 总备弹按史实
```

硬性约束（有脚本校验）：
- `loadout.ap + loadout.apcr + loadout.he === ammo.shell`，不等就是 bug。
- 没有史实 APCR 的车：**整个省略 `apcrShell` 字段**，且 `loadout.apcr = 0`（UI 会自动不显示 APCR 行）。SU-100、IS-2、SU-152、猎虎等就是这样。
- `apcrShell` 存在时，`loadout.apcr` 必须 > 0。

## 3. 穿深两点拟合法（pen / penDrop 怎么从史实曲线算出来）

游戏内公式（shell.js / ai.js 统一）：

```
pen(d) = shellPen × (1 − shellPenDrop × d/1000)     // d 单位米
```

录入步骤：
1. 从权威来源查该弹 **30° 口径** 的 500m 与 2000m 穿深，记 p500、p2000（有 1000/1500 更好，可校验线性度）。
2. 解衰减：由 `p2000/p500 = (1−2x)/(1−0.5x)` 解出 `x = shellPenDrop`。
3. 回代 0m：`shellPen = p500 / (1 − 0.5·shellPenDrop)`。
4. 把史实曲线写进字段注释备查（格式：`史实30° 110@500/99@1000/91@1500/83@2000`）。

**验算示例（虎式 PzGr.39）**：110@500、83@2000 → 比值 0.7545 → 解得 drop ≈ 0.15 → pen0 = 110/(1−0.075) ≈ **119**。即 `shellPen: 119, shellPenDrop: 0.15`。游戏内 500m ≈ 110、2000m ≈ 83，与史实一致。

只有单一距离数据时，用同炮族/同弹种的已知 drop 做参考，并在注释里标注"折中估值（来源冲突）"——猎虎 230 就是这么处理的。

## 4. APCR（次口径钨芯弹）规则

- 快捷键 **3**（1=AP、2=HE、3=APCR），SHELL_TYPES.apcr 已内置：跳弹角更苛刻、破片系数 0.65（杀伤后效弱于 AP），无需逐车调。
- **配弹只给史实下限**：史料记载"每车 3–6 发"就只给 **3 发**；全车 APCR 配弹区间 2–5 发，防止稀释平衡（1944 后钨短缺，史实上本就稀少）。
- APCR 特征：0m 穿深显著高于 AP，但 drop 大得多（BR-365P 达 0.33/km），远距离迅速衰减甚至不如 AP——这是史实特性，保留，别为了手感抹平。
- AI 会用 APCR：AP 无解但 APCR 可穿时自动切（ai.js `_selectShell`），加新车无需额外处理。

## 5. HE 与备弹

- `heVelocity` 按**炮族**定，不要照抄 AP 初速（例：四号 KwK40 的 HE 只有 550 m/s，AP 是 750）。
- 大口径榴弹炮车（SU-152 / ISU-152 / 猎虎）：史实以 HE 为主，配弹比例体现这一点（152 车族 4 AP / 16–17 HE）。
- `heShell.power` 威力系数分档见 §10——它决定 HE 未击穿时的毁伤强度，≥2 才启用大口径机制，别随手填。
- 备弹总量按史实编制数：虎式 92、虎王 86、KV-1 111、T-34-85 60、黄鼠狼 27……查不到就用同底盘同炮的车，注释说明。

## 6. 加新车 checklist

1. 查史实：主炮型号 → 弹型号（AP/APCR/HE）→ 30° 穿深曲线 → 初速 → 备弹量与弹药配比。
2. 按 §3 拟合 `shellPen` / `shellPenDrop`；有 APCR 史实才加 `apcrShell`（2–5 发）。
3. **必填 `caliber`**（mm 主炮口径整数）：跳弹口径碾压（§9）与弹着尘堆都依赖它，漏填会静默按 75mm 算。
4. 定 `heShell.power` 档（§10）：<100mm 给 1.0，122/128 给 2.2/2.4，152 给 3.0。
5. 填 `loadout`，自检合计 == `ammo.shell`。
6. 跑数据一致性校验（参照迁移脚本末尾的校验段，或直接照抄该车组字段格式）。
7. 跑 `node scripts/smoke_apcr.cjs` 做浏览器冒烟（需 8081 静态服务在跑）：弹药面板行数、3 键切弹、开火耗弹、无控制台报错。
8. 更新 `炮弹数据总表.md`，写明来源。

## 7. 数据来源优先级

1. **WWII Ballistics: Armor and Gunnery**（Lorin Bird & Robert Livingston）——美/英/德/苏穿深换算基准。
2. 苏联：**Russian Battlefield**（battlefield.ru）及苏军靶场报告——注意原始数据多为 0° 口径，需换算。
3. 德国：Kampftruppen / Wa Prüf 靶场表（多为 30°，可直接用）。
4. 美国：TM 9-1907 等弹道表（注意部分为 0° 或 20° 口径）。
5. 游戏Wiki / 论坛估算**只能交叉印证，不能单独作据**。

## 8. 平衡旋钮（调手感时动这里，别改史实数值）

- `SHELL_TYPES.apcr.spallMult`（0.65）：APCR 后效强弱。
- `SHELL_TYPES.*.跳弹角`：各弹种跳弹阈值。
- APCR 配弹发数（2–5 区间内的增减）。
- 史实数值本身（pen/velocity/drop）**不作为平衡手段**——某车过强时优先动装甲、装填、配弹，不动穿深。

## 9. 跳弹概率曲线（2026-09-23 史实化，替代旧"固定角度必跳"）

旧机制是到固定角度 100% 跳弹，实战里大倾角装甲无敌、手感假。新机制（tank.js `applyHit`）：

```
P(跳弹) = clamp((入射角 − ricStart) / (ricFull − ricStart), 0, 1) × ricK × 口径碾压系数
```

- **弹种曲线**（`SHELL_TYPES`）：AP `ricStart 50 / ricFull 80 / ricK 0.85`（被帽转正，概率略降）；APCR `45 / 72 / 1.3`（钨芯弹更脆更滑）；HE **永不跳弹**。
- **口径碾压**（`DAMAGE_RULES.ricochet.overmatch`）：口径/板厚 ≥3 → 概率 ×0.1（薄板压不住大弹，塑性失效而非弹跳）；2.5~3 → ×0.3；1.5~2.5 → ×0.7；<1.5 → ×1。封顶 `maxP 0.97`，无绝对必跳。
- 依赖每车 `caliber` 字段（缺失按 75mm 静默处理——加新车必填，见 §6）。
- 效果：50° 以下 AP 必不跳，50–80° 之间概率线性爬升，大口径打小倾角薄板（如 152 打四号 30mm 侧甲）几乎不跳。

## 10. 大口径 HE 毁伤体系（hePower 分档，2026-09-23）

HE 未击穿走 tank.js `applyHESplash`，毁伤强度由 `heShell.power`（威力系数 P，88mm=1 基准）驱动。**P≥2（`heShock.minPower`）才启用大口径机制**，88/90mm(P=1) 完全走旧路径不受影响。

当前档位：SU-100 100mm=1.4、IS-2 122mm=2.2、猎虎 128mm=2.4、SU-152/ISU-152 152mm=3.0。加新车按口径就近入档。

`heShell` 完整字段：`{ power, penMult, nearMissR, velMult }`——penMult 是 HE 穿深系数（152 给 0.12，可掀薄顶甲）；nearMissR 是落地近失弹作用半径（0=无）；velMult 初速系数。

P≥2 时在基础毁伤（断带/伤观瞄/伤炮闩/薄甲震伤，概率随 P 上浮）之上叠加四层（`DAMAGE_RULES.heShock`）：

1. **必中项**：命中行走部必断带；命中车体 70% 冲击波断带；命中炮塔必伤观瞄+炮闩。
2. **内崩落**：厚板（>薄甲阈值）被命中 → 内层崩落破片伤乘员。概率 `min(0.65, 0.2×(P−1) + 0.002×板厚)`，波及 2m 内最多 2 人，阵亡率 `min(0.55, 0.35+0.075×(P−1))`。
3. **结构震伤**：方向机/发动机各 `min(0.6, 0.3×(P−1))` 概率受损（命中部位对应模块 ×1.5），伤害 20–40。
4. **超压毁伤**：整车毁伤判定。概率按面甲分档（P=3 基准：≤85mm 35% / ≤150mm 15% / 超重甲 5%）× `(P−1)/2`。触发后 2.8m 内最多 3 名乘员各 70% 阵亡，并重创炮闩+方向机/发动机（40–70 伤害）。

实测定标（`scripts/live_he_e2e.cjs` 端到端实弹验证）：ISU-152 打四号 J 平均 1–2 发解决（超压震死乘员→弃车），打虎式正面约 15%/发 整车毁伤率，另有崩落/断带/模块伤兜底——152 级 HE 对中甲目标致命、对重甲有稳定毁伤但不秒杀，符合史实量级。蒙特卡洛基准在 `scripts/he_damage_sim.mjs`。

## 11. 关键坑：shells.fire() 是字段白名单（2026-09-24 事故）

tank.js `fire()` 组装的炮弹数据（`hePower`、`nearMissR`、`caliber`……）**不会自动进入飞行中的炮弹对象**——shell.js `ShellManager.fire()` 手动挑字段复制，是白名单。2026-09-23 加了 hePower 体系却漏了这里，导致实战全部 HE 按 P=1 结算（大口径机制全灭），而所有直接调 applyHESplash 的测试都绕过了这个函数，全部误报通过。

**教训/规则**：
- 给炮弹加任何新字段，必须同步两处：tank.js `fire()` 的返回对象 + shell.js `fire()` 的入队复制。改完全局搜一下字段名确认两处都在。
- 涉及"发射→飞行→命中"链路的改动，**必须用 `scripts/live_he_e2e.cjs` 这类端到端实弹测试验证**（真实 fire() → 弹道 → resolveHitZone → 结算），不能只调内部函数单测。
